# Registered model profiles

`byteshape.json`, `glimmer.json`, and `flash.json` pin the exact Wright artifacts, runtime/library hashes, launch arguments and complete settings. Configurations have content-derived profile IDs. Glimmer includes its patched libllama identity and the original DFlash head; Flash includes all four target shards, projector and MTP head plus its MMQ environment.

Production `/profiles` and Astra selection expose only the selected model's llama.cpp profiles. Ollama references are retained solely for standalone comparison scripts. They never run through Optimize. ByteShape/Glimmer each require one L40; Flash requires three on one node. The compute worker verifies assets and runtime before loading. Descriptive settings become writable only with an explicit validated adapter mapping.

The November 7 Industrial Revolution campaigns now provide six additional selectable, complete configurations: ByteShape A2; Glimmer A3/D3/B3; Flash A5/C5. These are copied exactly from the committed experiment receipts, including their content-derived IDs. Matching control observations are also linked to existing profiles. The full 50 observations still reach Astra as CANON evidence. The shortlist avoids combining winners from different tracks; it does not change the base profile, runtime, context, KV, or Ollama defaults. New candidates still require the ordinary production correctness check and timing probe before success.

For the short essay Astra prioritizes matching campaign evidence: ByteShape MTP3/0.75, Glimmer's strongest observed DFlash15/0.25 candidate (with smaller-draft and batch alternatives), and Flash's measured MTP2 candidates. Small single-run differences are not guaranteed gains; temperatures nearer 1 are preferred only when comparable decode evidence supports them. Explicit sampling/context locks and failures take precedence.
